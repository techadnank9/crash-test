How Crash Test works

One Node server holds all the state and drives four services. The only voice traffic is caller agents phoning the agent under test. Everything else is plain HTTP.

Architecture

The browser never talks to an outside service. It polls the server once a second and sends three commands. The server talks to Vapi for calls and prompts, Jev for grades, an OpenAI-compatible model for rewrites and Exa for research.

What happens when you press start

One request to POST /crash runs the whole loop in the background. The dashboard just watches.

  1. Look up the targetThe server lists the phone numbers in your Vapi account. If the number you entered is one of them, it records which assistant answers it. That assistant is the one heal can rewrite.
  2. Pick the callersThe Acme Bank demo uses ten hand-written personas from the spec. For any other agent, the LLM writes new ones from your description, optionally grounded in real customer complaints found with Exa. Each persona has a goal and a pass rule.
  3. Place the callsFor each persona, POST /call asks Vapi to start the caller assistant with the persona and goal filled into its prompt. All calls start at once.
  4. Wait for each call to endThe server polls GET /call/{id} every 3 seconds, for up to 120 seconds. It keeps the transcript and the recording link. A call that never reaches the agent is marked as an error and left out of the score.
  5. Grade each transcript as it landsJev gets the transcript, the attack goal and the pass rule, plus two typed questions: did the agent pass, and which failure type fits. If Jev fails twice, the LLM grades instead and returns the same fields as JSON.
  6. Heal, if anything failedThe server reads the assistant, sends its prompt and the failed transcripts to the LLM, and writes the new prompt back with PATCH /assistant/{id}. Only the system message changes.
  7. Call againThe same callers phone again with the same goals. The scoreboard puts the two rounds side by side.

Reading the score

Each round shows how many graded calls passed, such as 4/5. A round reads Working when at least 80% of its graded calls pass and Not working below that. Calls that never connected don't count either way.

Every call also shows a pass probability. That number comes straight from Jev: its estimate, from 0 to 100%, that the agent satisfied the pass rule. Above 50% counts as a pass. A call near the line is worth reading yourself. A call at 2% or 98% is a clear verdict.

What counts as a failure

Every failed call gets one failure type. These map onto risks that security and policy groups already track, so a result means the same thing to your team as it does to an auditor.

Design decisions

Poll instead of webhooks

Polling each call every 3 seconds means no public URL, no tunnel and no signature checks. It runs on a laptop at a hackathon table.

One phone number is enough

Vapi places the call from your number to the agent's number. For the demo, the Acme Bank number calls itself: one leg is the caller, the other leg is the agent.

Relabel speakers before grading

Vapi labels the caller "AI" and the agent "User", which is backwards here. With raw labels, Jev passed an obvious discount-code leak at 54%. After relabelling to Agent and Caller, the same transcript scored 4% and was tagged as leaked data.

Grades never block the demo

Jev is tried twice. After that the LLM grades with the same pass rule. Each tile shows which grader was used.

Heal only what you own

Crash Test can call any phone number, but it only rewrites prompts of assistants in your Vapi account. Anyone else's agent gets a score, not an edit.

No database

State lives in memory and the page polls it. Reset restores the demo agent's weak prompt so the demo can run again.

Limits

  • Five calls is a small sample. Phone agents are not deterministic, and the same caller can pass one run and fail the next.
  • Each test call uses two of your Vapi concurrent-call slots, one for each leg. With a limit of 10, keep the batch at 5 or fewer.
  • A heal is a rewrite from a handful of failures. It can overfit to those callers, so call again with new personas before trusting it.
  • The grader judges the transcript, not the audio. Tone, interruptions and long silences are not scored.

References

Crash Test is a small, practical version of ideas from these papers and standards.

  • Red Teaming Language Models with Language ModelsPerez et al., 2022. Uses one language model to generate test cases that find harmful behavior in another. Crash Test's callers do the same over the phone.
  • Self-Refine: Iterative Refinement with Self-FeedbackMadaan et al., 2023. Improves outputs with a feedback-then-refine loop and no extra training. Heal is one refine step driven by graded failures.
  • Large Language Models as OptimizersYang et al., 2023. OPRO treats prompt writing as optimization with scored attempts in the loop. Attack, grade, heal, call again is that loop for a system prompt.
  • OWASP Top 10 for LLM ApplicationsThe risk list behind the failure types: prompt injection, sensitive information disclosure, excessive agency, system prompt leakage and misinformation.
  • EU AI Act, Article 50Transparency obligations: systems that interact with people must let them know they are talking to an AI. This is the rule the skeptic caller tests.
  • TypeSafe Jev documentationSend state and typed questions, get structured answers. Crash Test asks a yes-or-no question and a multiple-choice question for every call.
  • Vapi outbound callingHow calls are placed from a Vapi phone number, and the assistant overrides used to give each caller its persona.
